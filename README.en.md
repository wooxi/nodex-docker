# NodeX · Container

Container image for NodeX. Ships Xray and Hysteria 2 kernels plus a built-in web UI.

[中文](README.md) · [Source](https://github.com/wooxi/nodex) · [Router build](https://github.com/wooxi/nodex-luci) · [Control panel](https://github.com/wooxi/xpanel)

---

## About

This repository only packages. It carries no Go source. The `Dockerfile` pulls from [wooxi/nodex](https://github.com/wooxi/nodex) in a multi-stage build, compiles the frontend and binary, and installs them alongside both kernels in the runtime image.

Protocols, node management and panel integration are documented in the [main repository](https://github.com/wooxi/nodex). This repository covers what is specific to containers.

Images are published to GHCR:

```bash
docker pull ghcr.io/wooxi/nodex-docker:latest
```

## Deploy

`docker-compose.yml`:

```yaml
services:
  nodex:
    image: ghcr.io/wooxi/nodex-docker:latest
    container_name: nodex
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./data:/etc/nodex
    environment:
      - TZ=Asia/Shanghai
```

```bash
docker compose up -d
```

Open `http://<host>:8888` and set the admin password.

`network_mode: host` is required. Node ports are issued by the panel; mapping them one by one is not practical.

### Building locally

```bash
docker build --build-arg SOURCE_REF=main -t nodex:latest .
```

Behind a slow link to public registries:

```bash
docker build \
  --build-arg NPM_REGISTRY=https://registry.npmmirror.com \
  --build-arg GOPROXY=https://goproxy.cn,direct \
  -t nodex:latest .
```

Build arguments:

| Argument | Default | Purpose |
|---|---|---|
| `SOURCE_REPO` | `https://github.com/wooxi/nodex.git` | source repository |
| `SOURCE_REF` | `main` | branch or tag |
| `NPM_REGISTRY` | `https://registry.npmjs.org` | frontend registry |
| `GOPROXY` | `https://proxy.golang.org,direct` | Go module proxy |
| `XRAY_VERSION` | see Dockerfile | bundled kernel version |
| `HYSTERIA_VERSION` | see Dockerfile | bundled kernel version |

## Data

Mounted at `/etc/nodex`:

| Path | Contents |
|---|---|
| `config.json` | entire configuration, generated by the UI |
| `bin/` | kernels updated from the UI, preferred over the image's copy |
| `hy2.crt` / `hy2.key` | self-signed certificate generated on first start, used when a node has none configured |
| logs | node and kernel logs |

Kernels can be upgraded from the UI. The new binary lands in `bin/` and survives container recreation — it takes precedence over the bundled version.

## Connecting a panel

1. Panel → Servers → add a node (v2ray or hysteria), note the **node ID**
2. Panel → Settings → copy the **communication key**
3. `http://<host>:8888` → Panel: enter panel URL and key
4. Nodes → add: enter node ID, pick protocol
5. Start

The panel can be [XPanel](https://github.com/wooxi/xpanel), Xboard, V2Board or any UniProxy-compatible implementation.

## Requirements

| Item | Requirement |
|---|---|
| Platform | `linux/amd64` |
| Base | `debian:bookworm-slim` with ca-certificates and openssl |
| Network | host networking, or equivalent full port reachability |

## Building

Pushing a tag builds and pushes `ghcr.io/wooxi/nodex-docker` through GitHub Actions. Upstream commits trigger a build via `repository_dispatch`, with a daily schedule as a fallback.
